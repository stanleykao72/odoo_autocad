# 規劃命令

## 用途

為功能需求或技術任務制定實作計畫，在寫程式碼前先確認方向。

---

## 執行流程

### Phase 1: 需求理解

1. 確認功能需求的範圍和目標
2. 識別涉及的現有元件
3. 評估對現有系統的影響

### Phase 2: 架構分析

1. 讀取相關的現有程式碼
2. 確認現有模式和慣例
3. 識別可重用的元件
4. 評估是否需要新增依賴

### Phase 3: 方案設計

提出 1-3 個可行方案，每個方案包含：
- 概述
- 涉及的檔案清單
- 新增/修改的元件
- 優缺點
- 預估複雜度

### Phase 4: 任務分解

將選定方案拆解為有序的任務：

```markdown
## 實作計畫

### 任務清單

1. [ ] {Task 1} — {Agent}
   - 檔案: {files}
   - 依賴: 無
2. [ ] {Task 2} — {Agent}
   - 檔案: {files}
   - 依賴: Task 1
3. [ ] {Task 3} — {Agent}
   - 檔案: {files}
   - 依賴: Task 1, Task 2

### 可平行任務
- Task A + Task B（無依賴）

### 關鍵路徑
Task 1 → Task 2 → Task 3
```

### Phase 5: 風險評估

- 技術風險（未知的 API、複雜的 COM 操作）
- 相容性風險（現有功能可能受影響）
- 測試風險（難以自動化測試的部分）

---

## 計畫模板

```markdown
# {功能名稱} 實作計畫

## 需求摘要
{1-2 句描述}

## 方案
### 方案 A: {name}
- 優點: {pros}
- 缺點: {cons}

## 選定方案
{方案 X}，原因：{reasoning}

## 任務清單
1. [ ] ...
2. [ ] ...

## 風險
- {risk 1}: {mitigation}

## 驗收標準
- [ ] {criterion 1}
- [ ] {criterion 2}
```
